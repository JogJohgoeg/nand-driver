`ArenaV3_1.sol` is a separate contract. The deployed v3 at

## Entries and tracks / 报名与赛道

| ID | Track | Inputs / outputs | State bits | Ranking |
|---|---|---|---|---|
| 0 | v1 | 15 / 2 | 0 | progress, then fewer elements |
| 1 | v2b | 15 / 4 | 0–8 | existing progress/finish-step score, then fewer elements |
| 2 | duck | 14 / 2 | 0–8 | goals descending, collision steps ascending, total steps ascending, elements ascending |

Exact ties keep the earlier entry. Duck runs eight fixed starts, at most 4,000
navigation steps each; `score` stores goals (0–8), while `collisionSteps` and
`totalSteps` retain the exact secondary metrics. `reportDuck` uses separate
integers because the full lexicographic tuple exceeds a uint32 scalar.

普通电路保留 `enter(cpu,id,track)`。组合电路使用
`enterComposite(composer,track)`；两者都支付本赛季报名费 0.2 BEM。
每个组合最多 8 个部件，合计最多 256 个 NAND/LATCH 元件、8 个状态位。
鸭子赛道先比 8 个固定起点中到达目标的数量，再比碰撞步数、总步数；
都相同时比较元件数量、报名先后。每次起跑状态清零；50 步零指令预热不计分。

The actual `../../duck/composite/CircuitGraph.sol` ABI is used, including
`owner()`, `nIn/nOut/nState()`, `partCount()`, and
`parts(i) -> (cpu,cid,nIn,nOut,nState)` (plural, five fields). Its
`inputWiring(i)` gives indices into external inputs followed by earlier parts'
outputs. `step(state,inputs)` returns `(newState,outputs)`, packed LSB-first;
part states concatenate at bit boundaries, not byte boundaries.

Admission requires composer ownership, factory recognition of **every** CPU,
actual on-chain part shapes matching their declarations, aggregate state count,
and the chosen track's declared input/output shape. It records a manifest of
runtime code hash, declared shape and ordered part metadata. Drive, report and
settlement check this manifest again. Re-entry after settlement pays again and
gets a new entry ID and zero state. Owning a composer does not require owning
its component circuit NFTs; component evaluation is public.

组合报名检查所有 CPU 的工厂认可状态、每个部件实际形状、总状态位及赛道形状。
组合所有者报名和领取奖金；不要求其同时拥有所有部件 NFT。记录的清单哈希在
驾驶、评分、结算时重新校验。赛季结束后需重新付费报名，状态清零。

## Drive and trust boundary / 执行与信任边界

Normal circuit `drive()` still uses the official Witness (`evaluate` or `beat`).
Composite `drive()` charges the same 0.005 BEM and calls the composer's **view**
`step` by STATICCALL, validating packed lengths/padding and storing the returned
state per entry in the Arena. Drivers share that entry's state. It emits `Drove`;
there is no composite Witness event, since the existing Witness accepts CPU
circuits, not composer addresses. `CircuitGraph.beat` is not called.

A generic interface cannot prove that arbitrary bytecode executes only its
declared parts. The manifest does not hash private wiring, proxy implementations,
or arbitrary hidden storage. This is **not permissionless proof of composition**.
The supported referee additionally reads `inputWiring`, reconstructs the official
circuits, checks 16 random transitions, and compares **every distinct visited
state/input row** with `composer.step` at one pinned block. Cache reuse is only
within that scoring run. Referee review must confirm constructor-fixed wiring
and the actual CircuitGraph implementation; context-dependent/mutable impostors
must not receive a report. A future trustless version needs implementation
attestation or a factory, not merely more metadata getters.

普通驾驶仍经 Witness；组合驾驶由 Arena 保存状态并静态调用 `step`，不产生
Witness 的事件。接口与清单不等于对任意合约的无信任证明：裁判必须核对实际
CircuitGraph 源码及不可变接线，并逐个已访问输入/状态组合交叉验证。
代理升级、隐藏逻辑和依赖调用上下文的伪装合约不应获准评分。

## Referee and reproduction / 裁判与复现

Duck uses **headless Chrome running the existing Microduck MuJoCo WASM + ONNX
runner**, not a Python physics approximation. `duck_runner.cjs` creates its own
Chrome target and uses `duck.reset`, `perception` and `policyStep`. Circuit
decisions come from `referee_graph.py`; state resets per start and carries
across navigation steps. The trace contains inputs, state, outputs, contacts and
qpos for every step. Termination is the existing goal radius / fall / timeout
rule. The source runner must be served from the reviewed duck checkout.

```sh
# From this directory; no browser wallet is used.
.venv/bin/python build.py --v3.1
.venv/bin/python test_arena_v31.py
# Serve the repo at 8794 and use a dedicated Chrome CDP at 9225.
# The default duck URL is the static duck/dist_pages/brain.html build (no HMR).
.venv/bin/python referee.py --track duck \
  --cpu 0x6Fb4089e7Cbaa9660Fd11056274Cbd8117EE5B38 --cid 281 \
  --entry ENTRY_ID --uri PUBLISHED_TRACE_URI
# Once a reviewed composer exists, replace --cpu/--cid with --composer ADDRESS.
# Composite v1 and v2b scoring are also supported via --track.
.venv/bin/python draft_v31.py --composer 0xc32baB9E0C5490b805cc944a50A7346254A645b3
# Optional: --arena NEW_ADDRESS --composer REVIEWED_ADDRESS
```

`test_results_v31.json` records local PyEVM gas (not a BSC gas quote). The full
mock-composer duck run reproduces **7 goals, 6 collision-free goals, 30 collision
steps, 15,174 total steps**, with 35 unique eth_call rows including the 16 random
checks. Tests also cover the real CircuitGraph ABI and a two-part graph with
6 state bits. Local EVM transactions are test fixtures only.

The deployed composer was also scored with real BSC eth_call at pinned block
**120894806**: 64 total elements (61 NAND + 3 LATCH), 52 unique state/input rows,
16/16 random cross-checks and the same 7/6/30/15174 result. It **ties #281** on

`traces/0xc32bab9e0c5490b805cc944a50a7346254a645b3_duck.json` and its report
calldata file. The report draft uses entry 0 as an explicit placeholder; regenerate
with the newly assigned entry ID before any separately authorized submission.
The trace URI is a proposed publication path, not a claim that it was uploaded.

真实 BSC 固定区块 120894806 上也验证了 52 种状态/输入转换；组合结果与 #281

## Season 0 migration / 第 0 赛季迁移

1. v3 is not upgradeable. Keep its address, entry IDs, reports and read-only
   history. Its season-0 entries are #279 (entry 0, v1) and #280 (entry 1, v2b).
2. A separately approved deployment creates a fresh v3.1 season 0. Owners must
   approve the new spender and enter/pay again. There is no administrative
   import that bypasses ownership or fees. Entry IDs are newly assigned.
3. Re-verify the original traces under unchanged rules before reporting to the
   new entry IDs. Duck/composites require their own new traces. Index both
   `CompositeEntered` and `DuckScored`; old leaderboard event parsing alone
   cannot display the new fields.
4. The old 0.4 BEM pool cannot be swept into v3.1: v3 has no arbitrary withdrawal.
   Any old settlement needs separate authorization and retains its 10% burn,
   60% prize allocation and rollover **in the old contract**. Baseline/house or
   EMPTY slots receive nothing; their shares stay in that contract. Never
   describe a UI address switch as transferring pool funds.
5. v3.1 retains the same 10/60/30 arithmetic, global season advance, per-track
   best lookup and referee-selected three prize slots. It does not pretend that
   duck goals and road progress are numerically comparable across tracks.

旧 v3 不可升级，历史记录与资金保留。新合约需另行批准部署，原车主重新授权、
付费报名、核验并重新报告；编号不直接复制。旧池无管理员提取功能，不会自动
迁移。旧合约结算也需要单独授权，基线及空位的奖金继续留在旧池中。
三个赛道分别排名，共用三个由裁判指定的奖金名额，不跨赛道比较原始分数。
