# Agents-API 电路 #283、#284

> 把 agent 会话的控制规则做成链上电路：#283 是第一版，#284 加上熔断、原因码和分档付费。

::: buttons
- [在浏览器里拨动 #283 和 #284](https://nand.aihashrate.stream/agents-api/)
:::

## 它是什么

- 模型、工具、子 agent 都在链下。电路每拍只决定下一步做什么：调模型、调哪类工具、派不派子 agent、压不压缩上下文、停不停、付不付钱。
- 规则刻在链上，谁都能用 `step()` 逐门重算，看某次执行是不是照规矩来的。
- 两颗都在 BNB Chain 的 TapeOut CPU `0x6Fb4089e7Cbaa9660Fd11056274Cbd8117EE5B38` 上，2026-09-11 同一天上链。

## 两颗电路

| 项 | #283 | #284 |
|---|---|---|
| 构建 | v2 | v5 |
| 输入 / 输出 / 状态位 | 16 / 15 / 10 | 16 / 17 / 23 |
| NAND | 152 | 295 |
| LATCH | 10 | 23 |
| 网表 | 1,104 字节，sha256 `93d65a3634679190…` | 2,157 字节，sha256 `de800761487244af…` |
| 区块 | 121240525 | 121331172 |
| 上链后抽查 | 64 组 `step()`，和本地一致 | 64 组 `step()`，和本地一致 |

链上网表按位核对见[自己核对](../start/verify.md)最后一节。

## #284 加了什么

| 项 | #283 | #284 | 触发时的原因码 |
|---|---|---|---|
| 轮数上限（调模型和压缩都算一轮） | 7 | 255 | 2 |
| 工具失败重试 | 1 次 | 3 次，第 4 次失败就停 | 3 |
| 同时跑的子 agent | 3 个 | 7 个 | — |
| 子 agent 失败（等 3 拍没回音也算一次） | 没有 | 第 3 次停 | 4 |
| 压缩没效果 | 会卡死 | 连续压缩 3 次后上下文还满就停 | 6 |
| 连续查工具定义 | 不限 | 最多连续 3 次，再要就停 | 7 |
| 预算用完 / 密钥被拒 | 停 | 停 | 1 / 5 |
| 付费 | 1 位 | 2 位：0 不付、1 部分、2 全额 | — |

- 所有熔断都是单向的：一旦停，就停在 DONE，之后不管输入什么，输出都是 0。
- 付费位只在完成那一拍等于评判结果，别的时候都是 0。

## 怎么证明它对

- #283：状态加输入一共 2^26 种，全部穷举，和规格 0 处不一致。
- #284：2^39 种穷举不了，用 SAT 求解器证明。
  1. 规格走两条独立的路变成网表（517 门和 289 门），证明两者在全部 2^39 种上等价；封装后的链上字节再证一次。
  2. 16 条安全性质逐条证明对每个状态、每个输入都成立，比如：DONE 出不去；付费一定伴随完成和评判通过；原因码非 0 当且仅当停机；各计数器不越界。
  3. 另一个模型只看文字规格独立写了一份 Verilog（302 门），和参考对比等价。

## 跑过的会话

- #283：让几个不同的模型当办事员，做同一道题「1000 以内质数之和」，答案 76127 才付费。每一拍都和链上 `step()` 逐位一致。
- #284：三个模型各跑一局（5、5、7 拍），每拍和链上 `step()` 一致，都以全额付费结束。

## 自己调一次

```sh 在链上跑一拍 #284（要装 Foundry 的 cast）
cast call 0x6Fb4089e7Cbaa9660Fd11056274Cbd8117EE5B38 \
  "step(uint256,bytes,bytes)(bytes,bytes)" \
  284 0x89ab14 0x07a0 \
  --rpc-url https://bsc-rpc.publicnode.com
```

- 状态 3 字节（23 位），输入 2 字节（16 位），输出 3 字节（17 位）。第 i 位放在第 i/8 字节的第 i%8 位。
- 这组是上链后抽查过的：应该返回新状态 `0x89ab0c`、输出 `0x000100`。
