 NAND tool: checking netlist…



A derivative of the Pi browser workspace · MiniCPM5-2B Space (upstream by townbox, Apache-2.0) — upstream unchanged, plus one added tool: nand_step.

 Model OpenBMB MiniCPM5-2B · Agent Pi · Shell just-bash · Inference Transformers.js + ONNX Runtime.



 NAND netlist tool — what it is, and what it is not
 
What this is

 
    
  
  • The upstream “Pi, entirely in your browser” Space — MiniCPM5-2B on WebGPU, a just-bash virtual filesystem, an xterm terminal — unchanged, plus one addition: a nand_step tool the agent can call.
    • 
  
  • nand_step evaluates a real 386-gate NAND netlist, gate by gate, in a separate Web Worker. It is not a lookup table and not an approximation: the gates are evaluated in index order over a wire table, the way silicon would.
    • 
  
  • The netlist maps 14 input bits (two 7-bit cell indices on an 11×11 grid — bits 0–6 the agent cell, bits 7–13 the target cell, least-significant bit first) onto 3 output bits that encode the next move: 0 NOOP, 1 DOWN, 2 UP, 3 LEFT, 4 RIGHT.
    • 
  
  • Every call prints its exact input and output bits, so each step is auditable against the convention above.
    • 
  
  • The chip in the corner is live. On page load the worker evaluates all 11⁴ = 14,641 legal (agent, target) pairs and checks that the output is NOOP exactly when the agent sits on the target, and otherwise a move that strictly decreases the Manhattan distance; it also compares every output against an independent reference implementation of the same netlist.
    • 
 

 
What this is not

 
    
  
  • Checked against the chain, live. The same netlist is burned as cid 287 of a CPU contract on BNB Chain. Every nand_step call also re-evaluates it there with a read-only eth_call and prints a second line showing what the chain returned and whether it agrees (see “on-chain cross-check” below).
    • 
  
  • Not a general-purpose computer. The netlist is fixed and combinational. The tool reads four coordinates and returns one move; it cannot run programs, hold state, or change its function.
    • 
  
  • Not learned or trained here. The netlist was synthesized elsewhere; this page only evaluates it. The language model decides when to call the tool; the netlist does the arithmetic.
    • 
  
  • Not immune to model error. MiniCPM5-2B may pass wrong coordinates or misread the result. Every argument is clamped to 0–10 and the exact bits are always echoed, so a misuse is visible rather than silent.
    • 
  
  • The self-check proves the evaluator matches the proven policy on all legal states. It says nothing about provenance, the on-chain artifact, or the training data.
    • 
 


On-chain cross-check — live on every call


The same netlist is burned on BNB Chain as cid 287 of the CPU contract 0x6Fb4089e7Cbaa9660Fd11056274Cbd8117EE5B38. Each nand_step result is followed by a line that re-evaluates that on-chain circuit with a read-only eth_call — no signature, no gas spent, no wallet — and prints what it returned and whether it agrees with the in-browser netlist.


The call is step(uint256,bytes,bytes) (selector 0xe8281a1a) with cid 287, an empty state, and the same 14 input bits this page packs LSB-first; the second returned bytes hold the output bits, of which bits 0–2 are the action. Measured step gas is 937,314 and the RPC answers in roughly 100 ms, so it runs on every call rather than behind a button. The check degrades gracefully: if the RPC is slow or fails, the in-browser result still comes back and the line says the chain check was unavailable. Nothing is faked either way.
