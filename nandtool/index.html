 NAND tool: checking netlist…



A derivative of the Pi browser workspace · MiniCPM5-2B Space (upstream by townbox, Apache-2.0). Changed here: the model is replaced by impossible LLM, a 54,147-gate NAND netlist transcribed from OpenBMB MiniCPM5-2B, and one tool is added: nand_step.
 Agent Pi · Shell just-bash · Tokenizer MiniCPM5 (Transformers.js).



 The brain is a NAND netlist — what that means
 
What answers you

 
    
  
  • Every token of Pi's reply is produced by one evaluation of a 54,147-gate NAND netlist (0 latches, 102 inputs, 13 outputs), gate by gate on your CPU — the same netlist as the impossible LLM page. There are no weights and no GPU; a 48-token reply takes a few milliseconds of gate evaluation.
    • 
  
  • The netlist sees the last 6 MiniCPM5 tokens (17 bits each) and returns a 13-bit code, which indexes one of 8,192 token ids. It is greedy and stateless.
    • 
  
  • Because a 6-token window over the chat template would always see the same template tail, the reply continues your last message. Pi's thinking phase is skipped and a reply ends after 48 tokens.
    • 
 

 
What to expect

 
    
  
  • It is not MiniCPM5-2B. It agrees with the teacher's next token about 23% near its training text and about 11% far from it; the teacher itself is right about 49%.
    • 
  
  • It was transcribed from Wikipedia-style text, so it writes that style (@-@,  , , years and headings). Outside that distribution it falls back to the most common tokens and loops, e.g. “the 2008 , the 2008 …”. That is the model, not a page bug.
    • 
  
  • It cannot call tools. It never emits the tool-call markup, so the shell, the files and nand_step are only usable by you, not by the agent. The workspace still works from the Shell panel.
    • 
 

 
How this page was checked

 
    
  
  • The in-browser gate evaluator matches an independent Python reference (tapeout_asic/golden.py) on 300/300 inputs.
    • 
  
  • Tokenization and bit packing match the offline pipeline on all 200 reference prompts, and 16-token continuations are identical to the impossible LLM page.
    • 
  
  • The netlist is not on chain — it was not burned — so, unlike nand_step, its tokens are not cross-checked against BNB Chain.
    • 
 

 
The nand_step tool (unchanged)

 
A 386-gate grid-navigation netlist, exhaustively self-checked on load (the chip in the corner) and cross-checked on every call against the same circuit burned as cid 287 on BNB Chain with a read-only eth_call. With the netlist brain the agent no longer calls it (see above); the chip still self-checks on every load. Details in NAND-TOOL.md.
