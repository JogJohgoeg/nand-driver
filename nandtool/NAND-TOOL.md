# The nand_step tool - a real 386-gate NAND netlist the agent can call

This directory is a clone of the "Pi, entirely in your browser" Space
(MiniCPM5-2B on WebGPU, just-bash virtual filesystem, xterm terminal), with
**one addition the upstream Space cannot do**: a tool named `nand_step` that
the in-browser agent can invoke, and whose implementation is a **NAND netlist
evaluated gate by gate in a Web Worker** - not simulated, not a lookup table.

## The tool

```text
nand_step(agent_row, agent_col, target_row, target_col)   // each an integer 0-10
```

Row/column 0,0 is the top-left corner of an 11x11 grid. Every argument is
clamped to 0-10, so a model error cannot index outside the grid. The tool
spawns a Web Worker (`assets/nand.worker.js`), evaluates the netlist on the
14 input bits, and returns multi-line text showing the **exact bit pattern**:

```text
NAND netlist step - 386 NAND gates evaluated gate by gate in a Web Worker
agent cell (5,5) index 60  |  target cell (0,0) index 0
input bits (14, LSB-first; bits 0-6 = agent cell index, bits 7-13 = target cell index): 00111100000000
output bits (3): 010  ->  action 2 (UP)
next cell (4,5)  |  distance to target 10 -> 9
Worker self-check passed: 14641/14641 legal states match an independent reference implementation of the same netlist; policy invariants verified.
```

Bit convention (verified exhaustively, see below): bits 0-6 hold the agent
cell index and bits 7-13 hold the target cell index, both least-significant
bit first. The 3 output bits encode the action: 0 NOOP, 1 DOWN, 2 UP, 3 LEFT,
4 RIGHT. The input and output bits are echoed on every call so each step is
auditable against the convention.

## How the netlist is evaluated

The netlist comes from
`circuits/_scratch/tapeout_asic/puf/netlist_resyn_squared14_struct.json`
(386 NAND gates, 0 latches, 14 inputs, 3 outputs, stored as a hex string of
2-bit gate descriptors). `assets/nand.worker.js` is self-contained: it holds
the hex, decodes it into a gate table, and evaluates the gates **in index
order over a wire array**, the way the silicon would. Nothing is
pre-computed; every call evaluates all 386 gates on the given input.

## Verification

1. **Exhaustive self-check at runtime.** When the worker starts (both the
   badge instance and the tool instance) it evaluates all 11^4 = 14,641 legal
   (agent, target) pairs and asserts, for every one of them:
   - the output is NOOP exactly when the agent sits on the target;
   - otherwise the move strictly decreases the Manhattan distance to the
     target (zero invalid moves, zero non-decreasing moves);
   - the output matches an **independent reference implementation** of the
     same netlist generated by a separate script from the same hex.
   Result on this build: 14641/14641 match, 0 mismatches, 0 invariant
   violations, 386 gates.
2. **Tool object tested end to end.** The injected tool`s `execute` was driven
   with the real worker under node: name/label/schema checks, the exact
   `{content:[{type:"text",text}],details:{}}` result shape the chat protocol
   requires (a bare string would be silently dropped), the clamping of
   out-of-range arguments, and correct actions for (5,5)->(0,0) = UP,
   co-located (0,0)->(0,0) = NOOP, clamped (10,0)->(10,10) = RIGHT.
3. **Real-browser check.** The page was opened in real Chrome (headless,
   driven over the Chrome DevTools Protocol): the app loads, the badge turns
   green with "386 gates, 14641/14641 legal states verified", clicking the
   badge opens the scope panel, the terminal and workspace render, and the
   **modified** agent bundle loads with zero console errors or exceptions.
4. **Bundle syntax.** The modified 2 MB agent bundle passes `node --check`
   as an ES module after injection.

## What this is NOT (read before trusting the number)
- **It is checked against the chain, live.** The same netlist is burned as an
  ASIC probe on BNB Chain (cid 287 of the CPU contract). Every `nand_step`
  call also re-evaluates that on-chain circuit with a read-only `eth_call`
  and prints what the chain returned and whether it agrees. See
  "On-chain cross-check" below.
- **It is not a general-purpose computer.** The netlist is fixed and
  combinational. The tool reads four coordinates and returns one move. It
  cannot run programs, hold state, or change its function.
- **It is not learned or trained here.** The netlist was synthesized
  elsewhere; this page only evaluates it. The language model decides when to
  call the tool; the netlist does the arithmetic.
- **It is not immune to model error.** MiniCPM5-2B may pass wrong coordinates
  or misread the result. Arguments are clamped to 0-10 and the bits are
  always echoed, so misuse is visible rather than silent.
- The self-check proves the **evaluator** matches the proven policy on all
  legal states. It says nothing about provenance, the on-chain artifact, or
  any training data.

## On-chain cross-check - live on every call

The same netlist is burned on BNB Chain as **cid 287** of the CPU contract
`0x6Fb4089e7Cbaa9660Fd11056274Cbd8117EE5B38`. Every `nand_step` result is
followed by a second line that re-evaluates that on-chain circuit with a
plain read-only `eth_call` - no signature, no gas spent, no wallet - and
prints what it returned and whether it agrees with the in-browser netlist.

**Status: resolved and agreeing.** The check lives in
`assets/chain-check.js` (dual export: `module.exports` under node,
`globalThis.__nandChain` in the browser) and was verified standalone under
node over 24 states spread across the 11x11 grid: **24 agree, 0 disagree,
0 unavailable**, roughly 100 ms per call. The agent cell at (5,5) heading to
(0,0) - cell index 60 - returns action 2 (UP) both in the browser and from
the chain.

**Recipe.** The earlier failure (a constant-zero on-chain output for every
encoding tried) was a calldata bug in this harness, not in the circuit. The
working call is `step(uint256,bytes,bytes)`, selector `0xe8281a1a`, with the
arguments packed as: cid 287, an **empty** state bytes, and the same 14
input bits this page packs LSB-first (`ar,ac,tr,tc` -> cell index
`row*11+col`), right-padded to a word. The output bits come back in the
**second** returned bytes, and bits 0-2 of its first byte are the action.
Measured step gas is 937,314. Reproduce against any BSC RPC, e.g.
`https://bsc-rpc.publicnode.com`.

**Graceful degradation.** The check never throws and never blocks: a 5 s
`AbortController` timeout, an RPC error, an empty result, or a decode
failure all produce an explicit `chain check unavailable: <why>` marker, and
the in-browser result is still returned. So the tool answers with or
without the chain, and it always says which.

## Files changed relative to the upstream Space

- `assets/nand.worker.js` - NEW. The gate-by-gate NAND evaluator, the
  embedded netlist hex, the exhaustive startup self-check, and the `step`
  handler. Self-contained classic worker, no dependencies.
- `assets/agent.worker-CS8jL-AS.js` - MODIFIED. Prepended a bridge
  (`__nandWorker` / `__nandRequest` / `__nandFmt`) and inserted the
  `nand_step` tool object as the first element of the tool array. 2,764
  bytes added to a 2,095,173-byte bundle; the rest is byte-identical.
  `node --check` passes; the browser test shows zero console errors.
- `assets/chain-check.js` - NEW. The read-only on-chain cross-check: calldata
  packing for `step(uint256,bytes,bytes)` at cid 287, the `eth_call` with a
  5 s timeout, output decoding, and the ready-to-print agreement line. Dual
  export, no dependencies.
- `index.html` - MODIFIED. A `#nt-badge` status chip and a `#nt-scope`
  details panel appended before `</body>` (all CSS under the `nt-` prefix,
  no upstream selectors touched), plus a small script that runs its own
  instance of `nand.worker.js` for the live self-check. Decoupled from the
  app bundle: the badge works even if the agent never loads.
