在小电脑上跑大模型

不用 FPGA，在 ARM 小电脑上纯 CPU 跑 17 亿参数的二值、三值模型。这页是实测速度和折算到板子的方法。

#结论

  • 模型：三值 Ternary-Bonsai-1.7B（PQ2_0，436 MiB）。质量接近二值 4B，体积和速度接近二值 1.7B，中文问答明显更好。
  • 板子：Cortex-A55 四核（带 NEON）优先，JH7110 排第二。
  • 速度：A55 四核折算约 8–8.5 tok/s（自写三值核），原实现约 4.9 tok/s。内存带宽上限约 11–13 tok/s。
  • 板上数字全部是折算，还没有上实机。

模型来自 Prism ML 的 Bonsai 系列（Apache-2.0）。

#怎么折算到板子

每种算两个上限，取小的那个。

带宽上限 = 实效内存带宽 ÷ 每个 token 读的字节数。每生成一个 token 要把权重整个读一遍，字节数约等于文件大小。

板子理论带宽实效按
A55 板（LPDDR4）8–10 GB/s60%，即 5–6 GB/s
JH7110约 11 GB/s2–4 GB/s（访存弱，待实机核）

算力上限：

  1. 用 llvm-mca（-mcpu=cortex-a55）数出计算循环每个权重要几拍。
  2. 每 token 拍数 = 权重数 × 每权重拍数，再加 8%（注意力、归一化、激活量化）。
  3. A55 四核 1.8 GHz、并行效率 0.85，约每秒 61 亿拍。
  4. tok/s = 每秒拍数 ÷ 每 token 拍数。主频 2.0 GHz 时乘 1.1。

例子，三值 1.7B：

计算核每权重拍数每 token 拍数tok/s
PrismML 原实现0.67约 12.5 亿4.9
自写切片核，单行 4 组0.41约 7.6 亿8.0
自写切片核，4 行一起0.385约 7.2 亿8.5

权重 17.2 亿个。每 token 读 0.46 GB，按 5–6 GB/s 算，带宽上限 11–13 tok/s。所以再往下优化，卡的是内存，不是计算。

#自写运行时 s6rt

  • 直接读 GGUF，或读转好布局的 TBW1 文件，自己算 Qwen3 前向。
  • x86 和 aarch64（NEON）两边的 logits 逐位相同。全程 -ffp-contract=off。
  • 自写 BPE 分词，和 llama.cpp 的分词逐个一致；终端里能直接打字提问（x86 上实测过一问一答，回答和直接运行逐字节相同；板上还没实跑）。
  • 有心跳，可以经 TapeBoot 启动，见从链上取固件。
  • x86 上 4 线程约 33 tok/s（AVX2）。这只说明能跑，不代表板上速度。

读 TBW1 比读 GGUF 现转省多少（x86 实测，A55 折算）：

项GGUF 现转TBW1 直读

到第一个心跳1.22–1.31 s0.09–0.17 s

冷启动从存储读约 460 MB 两条路一样。microSD 按 40–90 MB/s 要 5–12 s，这才是大头。
