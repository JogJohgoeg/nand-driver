# impossible LLM v2 — 重训报告（2026-09-16，Claude）

**主信息**：v2 是 **5,142,875 门**的 NAND 网表，读最近 6 个 token 和 4 个随机位。生成时**不再卡进短循环**：80 条提示用采样续写，卡住的比例为 0%，v1 是 100%。和教师的一致率（贪心）：维基 0.309、对话 0.303、网页 0.241、中文 0.219，v1 分别是 0.235 / 0.074 / 0.116 / 0.004。网表和查表语义在 550 万条输入上 0 处不一致。已上线 `/impossibleLLM/` 和 `/nandtool/`，v1 存档在 `/impossibleLLM/v1/`。**没有上链**。
**关联上下文**：v1 的构建流程和数字见 `../minicpm_cascade/BUILD_REPORT.md`；页面发布仓库是 `JogJohgoeg/nand-driver`。
**下一步判断**：门数每翻一倍，一致率只多约 0.014，而候选表项远没用完。继续提升应该靠更多带教师标签的语料（每 1 亿 token 约 2.2 小时 GPU），而不是加门。页面大小（网表记录现在 36 MB）也限制了继续加门。

## 1. 为什么 v1 会循环，为什么必须采样

- v1 里，只看最后一个词时，8,192 个词中有 7,352 个（90%）接 " the"，而 " the" → " 2008" → " ," → " the" 构成吸收环，所以大多数输入几步之内就会掉进去（node 实测）。
- 生成状态只有最后 6 个 token，所以**任何只看这 6 个 token 的确定性网表终究都会循环**。在只用维基的试验表上，把环上的表项改成教师的次优答案：改 60 处后，800 个起点仍然全部被困，环只是换了个位置。
- 因此 v2 的每个表项存教师在该上下文下最常给出的 3 个答案及其比例（这是教师面对不同更长上下文时实际给出的分布），由 4 个随机位按比例选一个（量化到 1/16）；随机位全为 0 就是贪心。查不到表时，按「没被任何层覆盖的位置」的标签分布做 16 格采样。

## 3. 建表（`v2_build.py`）

- 6 层回退：分别看最近 1…6 个 token，长的优先；只统计最常见答案至少出现 3 次的上下文。
- **按增益选表项**：一个上下文的价值 = 选它后多猜对的训练位置数，减去原本退回更低层就能猜对的数。门数按「增益 ÷ 每项成本」在各层之间分配，每项成本按实测综合结果校准。单这一项，在 3 万门时维基一致率就到 0.262，v1 在 5.4 万门时是 0.235。
- 最终表项数（看最近 1…6 个 token）：52,751 / 140,400 / 79,659 / 14,780 / 5,078 / 1,049，其中带备选答案的有 50,918 / 70,056 / 19,256 / 2,500 / 513 / 141。

## 4. 综合（`v2_chunk_synth.py`，build-host，328 秒）

- 每层每 3,000 个表项切成一块（共 100 块），每块单独用 yosys 综合（`abc -g NAND`，14 路并行）。每块输出「命中位 + 已按随机位选好的 13 位编码」，不命中时全为 0。
- 顶层小模块（4,284 门）把同一层各块的输出按位或起来，做最长匹配优先选择，再接 16 格回退表。
- 最后按 golden 编号拼成一个扁平网表：0 号线恒为 0、1 号线恒为 1、输入是 2..107 号；末尾 13 个门就是输出（经两次取反）。
- 每层门数（看最近 1…6 个 token）：994,656 / 2,443,605 / 1,333,318 / 247,994 / 93,247 / 25,745。

## 6. 端到端（页面流程，每步重新分词；`compare.mjs`，`results/compare_v1_v2.json`）

80 条提示（60 条维基原文 + 20 条手写，含对话、代码、中文），每条续写 48 个 token：

| | v1 | v2 贪心 | v2 采样 |
|---|---|---|---|
| 卡进周期 ≤8 的循环 | 100% | 3.7% | **0%** |
| 平均不同 token 数 | 7.5 | 24.3 | **34.5** |
| 每个 token 耗时 | node 0.2 ms | node 9.6 ms，Chrome 约 10–50 ms | 同左 |

页面修过的两个问题：
- 多字节字符原来按单个 token 解码，出现乱码 "�" 后又被喂回网表。现在每步对已生成的全部 token 整体解码。模型自己偶尔仍会输出半个汉字。
- 后台标签页会节流 `setTimeout`，主页改用 `MessageChannel` 让出主线程。

## 7. 限制

- 仍然写不出连贯的句子，会在中文、英文、代码之间乱跳。
- 一步的 gas 按容器模型约 116 亿（约 170 个区块），这个模型只在 5,300 门以内实测过，这里外推了约 1,000 倍。结论是不可能上链执行，也没有流片。
- 不会调用工具，没有记忆。
