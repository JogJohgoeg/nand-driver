# 翻书 · 动态容器

用户 2026-09-30：「做动态容器，每个静态上传当作一帧」。容器仍然只放静态文件，但每一次上传都是一帧，整本书在链上：

- `.flip/head.json` 指向最新帧卡；`.flip/f/<n>.json` 是帧卡：这一帧的全部文件（SHA-256、大小、类型、上传交易哈希）、上一张帧卡的哈希、链上时间。
- 帧卡一张扣一张（像页码）：撕页、换页、改页，往回翻时都对不上（`cardAt` / `readCard` 逐张核对 `prev`）。
- **当前帧**的文件就是网站本身，网关直接打开；**旧帧**从当初的 `putFile` / `appendChunk` 交易输入里解出来，核对帧卡里的哈希（`fileAt`）。
- 没变的文件不重传，沿用上一帧的记录；上一帧有、这一帧没有的文件从网站删掉（旧帧仍能翻回来）。
- **关键帧**（`publish(..., { keep: true })`）另存一份到 `.flip/k/<n>/`，永久在合约状态里，不依赖节点保留旧交易。实测公共 BSC 节点 21 天前的上传交易仍能取回（2026-09-30），节点会不会更早裁剪由它们决定，要永久可翻的帧就存关键帧。
- 上传自己估 gas 加两成：覆盖已有文件时，节点给的估计实测会差一点、交易刚好耗尽 gas 失败。

文件：`flip.js`（库，浏览器与 Node 通用，读链用 `../authenticator/tapeout.js`）、`site/`（翻书查看器：滑块、逐帧、播放）、`build.sh`（生成上链目录 `build/site`，`DEV=1` 保留本机分叉链地址）。

测试（先起分叉链并开隧道，见 `../authenticator/test/run_dev_fork.sh`、`dev-fork-setup.mjs`）：
- `node flipbook/test/fork_flip.mjs`：发布 6 帧（跳动的球），逐帧取回一致（交易 / 关键帧 / 状态三种来源）、没变的文件不重传、删文件、假帧卡被识别、写回后恢复、交易解码。15 项。
- `DEV=1 sh flipbook/build.sh && node flipbook/test/viewer.mjs`：查看器在浏览器里翻到每一帧、来源标注、播放。5 项。

## 通用发布工具 flip.mjs（用户：「做通用发布工具，要足够简单」）

```
node flipbook/flip.mjs auth <名字>          # 打开授权页：持有人签「授权上传钥匙 + 转一点 gas」，工具自己等到授权生效
node flipbook/flip.mjs <目录> <名字>        # 把目录发成新的一帧（--dry 只看要传什么；--keep 存关键帧）
node flipbook/flip.mjs log <名字>           # 列出所有帧（逐张核对）
node flipbook/flip.mjs done <名字>          # 退回剩余 gas，打开授权页去撤销
```

- 名字即 TapeOut 名字（288.732、1.2.245），自己解析出链和容器；上传钥匙在 `~/.flipbook_key.json`（第一次用时生成，只在本机）。
- 发布前列出每个文件：`+` 新增、`~` 改动、`=` 沿用、`-` 删掉、`!` **会盖掉容器里原有、但不属于这本书的文件**（比如原网站的 index.html）——有 `!` 时拒绝，要 `--force`。
- 授权页 `auth.html` 由工具在本机临时起服务打开，按参数显示容器、链、上传钥匙和金额；命令行轮询链上状态，不用回来说「签好了」。
- 查出来的 bug：`done` 退款写死 21000 gas、不看回执。持有人是合约钱包（Safe、EIP-7702 委托过的地址）时收钱要跑代码，转账失败却打印「✓ 退回」。
  分叉链上正好碰到：anvil 默认账户在 X Layer 主网上带着 7702 委托。修：先估 gas、发完核对回执，失败就明说、余额留在钥匙里。
- 测试 `node flipbook/test/cli.mjs`（分叉链）：干跑、没授权时拒绝、auth、发两帧只传改动、拒绝盖书外文件、log、done 真的退款。8 项。

主网演示（2026-09-30，X Layer 1.2.245，子目录 flipbook/，不动容器里原有的 21-nand-driver 页面）：https://1-2-245.aihashrate.stream/flipbook/
- 查看器 9 笔 + 6 帧，操作员 0x45fE…1d60（持有人在 `authenticator/deploy/setup_xlayer.html` 授权、转 0.005 OKB，用剩 0.0044 退回并撤销），发布命令 `node flipbook/publish_demo.mjs <帧数> --keep=<帧号>`。
- 主网上踩到一个真 bug：刚发完第 4 帧，下一次读到的 head 来自还没跟上的节点（仍是第 3 帧），又发了一个「第 4 帧」把帧卡盖掉。书仍然一环扣一环（1、2、3、4′、5、6），第一张第 4 帧卡只剩在交易历史里，第 4、5 帧图上的编号差一。
  修复：第 n 张帧卡已存在（问每个节点）就拒绝发布；写完 head 等每个节点都看到新 head 再返回。分叉链测试加了这一项（16/16）。

还没做：更通用的发布命令（持有人钱包或设备钥匙签）、大于 96 KB 的文件分段读、帧里是整站网页时在沙箱里渲染旧版本。
